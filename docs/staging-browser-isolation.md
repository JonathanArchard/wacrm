# Staging browser isolation

Runtime middleware adds an enforced CSP when the server network policy is restricted or the actual request hostname is staging. Existing report-only headers are preserved. CSP permits framework inline/eval scripts and inline styles for compatibility; this is network isolation, not nonce-based XSS hardening. Exact staging HTTPS and WSS origins replace wildcard Supabase access in the enforced policy. Browser SDK validates its configured project before creation and combines email and network fetch guards. Inbox image/video/audio/document URL validation, blob downloads and lightbox original links are restricted; staging download failures do not open a new tab.

Browser detection uses public site/project configuration and the actual staging hostname, not private runtime flags. A build with both public settings wrong on an alternate host may miss these explicit client guards; server middleware CSP remains the additional boundary. CSP cannot block all user-initiated top-level links or malicious extensions; no global fetch or WebSocket override. Realtime restriction relies on CSP and SDK project validation. SSRF/DNS rebinding and provider-side jobs/email remain open. Google Inter is imported through next/font/google (build-time fetch or framework handling, not an intended browser dependency); inspect generated CSS and actual headers before launch. Vinext middleware/header propagation, hydration, voice recording, blob previews, authentication and Realtime require actual staging browser testing after explicit deployment approval. No deployment or provider changes made. Source inventory remains partial.
